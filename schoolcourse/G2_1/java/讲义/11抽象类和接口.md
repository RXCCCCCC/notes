# Java 期末复习讲义：抽象类与接口 (Chapter 13)

## 一、 抽象类 (Abstract Classes)

### 1. 核心概念
*   **定义**：一种不能被实例化（不能 `new`）的类，专门设计用来被继承的。
*   **目的**：提供通用的属性和方法，作为子类的模板。
*   **关键字**：`abstract`

### 2. 关键规则 (考试常考判断题)
1.  **抽象方法**：
    *   使用 `abstract` 修饰，**没有方法体**（只有签名，以分号结束）。
    *   *规则*：如果一个类包含任何抽象方法，该类**必须**定义为抽象类。
2.  **非抽象子类**：
    *   如果一个普通类（Concrete Class）继承了抽象类，它必须**实现（Override）所有**父类的抽象方法。
    *   *特例*：如果子类没有实现所有抽象方法，那么子类也必须声明为 `abstract`。
3.  **构造方法**：
    *   **抽象类有构造方法吗？** **有！**
    *   *作用*：虽然不能 `new AbstractClass()`，但在创建子类对象时，会通过 `super()` 调用抽象类的构造方法来初始化父类定义的字段（如 `GeometricObject` 中的 `color`）。
4.  **无抽象方法的抽象类**：
    *   一个类可以定义为 `abstract`，即使它里面没有任何 `abstract` 方法。这样做的目的纯粹是为了禁止该类被实例化。
5.  **父类为普通类**：
    *   抽象类可以继承自一个普通类（例如 `GeometricObject` (abstract) extends `Object` (concrete)）。

### 3. 代码示例
```java
// 抽象类
public abstract class GeometricObject {
    private String color = "white";

    // 构造方法（不能直接new，但供子类super调用）
    protected GeometricObject() {
    }
    
    protected GeometricObject(String color) {
        this.color = color;
    }

    // 抽象方法（强制子类实现）
    public abstract double getArea();
    public abstract double getPerimeter();
}

// 具体子类
public class Circle extends GeometricObject {
    private double radius;

    public Circle(double radius) {
        super("blue"); // 调用抽象父类构造器
        this.radius = radius;
    }

    @Override
    public double getArea() { // 必须实现
        return Math.PI * radius * radius;
    }
    
    @Override
    public double getPerimeter() { // 必须实现
        return 2 * Math.PI * radius;
    }
}
```

## 二、 接口 (Interfaces)

### 1. 核心概念
*   **定义**：一种类似于类的结构，主要包含**常量**和**抽象方法**（Java 8之前）。它是对**行为**的抽象（Behavior Abstraction）。
*   **关系**：类和接口是 `implements`（实现），接口和接口是 `extends`（继承）。

### 2. 语法糖与省略规则 (易错点)
在接口中，某些修饰符是默认存在的，写不写效果一样，但**考试时简答题或改错题常考**：
*   **字段 (Fields)**：默认全是 `public static final`。
    *   `int K = 1;` 等同于 `public static final int K = 1;`
*   **方法 (Methods)**：默认全是 `public abstract`。
    *   `void p();` 等同于 `public abstract void p();`

### 3. 接口作为类型
接口可以像类一样作为引用变量的数据类型。
```java
// 多态性
Edible stuff = new Chicken(); // Chicken implements Edible
stuff.howToEat();
```

## 三、 两个核心接口 (Comparable & Cloneable)

这是本章最硬核的代码部分，**必考编程题或填空题**。

### 1. Comparable 接口 (`java.lang.Comparable<E>`)
*   **作用**：定义对象的自然排序规则。
*   **方法**：`public int compareTo(E o)`
*   **返回值逻辑**：
    *   `> 0`: 当前对象大
    *   `= 0`: 相等
    *   `< 0`: 当前对象小
*   **应用**：只有实现了此接口的类的数组，才能使用 `java.util.Arrays.sort(array)` 进行排序。

**代码模板**：
```java
public class Rectangle extends GeometricObject implements Comparable<Rectangle> {
    private double width, height;
    
    @Override
    public int compareTo(Rectangle o) {
        if (this.getArea() > o.getArea()) 
            return 1;
        else if (this.getArea() < o.getArea()) 
            return -1;
        else 
            return 0;
    }
}
```

### 2. Cloneable 接口 (`java.lang.Cloneable`)
*   **类型**：**标记接口 (Marker Interface)**。它里面是**空**的，没有任何方法。
*   **作用**：告诉 JVM 该类的对象可以被克隆。如果没实现该接口调用 `clone()`，会抛出 `CloneNotSupportedException`。
*   **实现机制**：必须重写 `Object` 类中的 `clone()` 方法，并提升访问权限为 `public`。

```java
// 1. 实现 Cloneable 接口
public class Sheep implements Cloneable {
    private String name;
    private int age;

    public Sheep(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // Getter 和 Setter 方法
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }
    public int getAge() { return age; }
    public void setAge(int age) { this.age = age; }

    @Override
    public String toString() {
        return "Sheep{name='" + name + "', age=" + age + "}";
    }

    // 2. 重写 clone() 方法
    // 注意：为了更好的类型安全，这里使用了协变返回类型（返回 Sheep 而不是 Object）
    @Override
    protected Sheep clone() {
        try {
            // 3. 调用父类 Object 的 clone 方法
            return (Sheep) super.clone();
        } catch (CloneNotSupportedException e) {
            // 这种情况理论上不会发生，因为本类已经实现了 Cloneable
            throw new AssertionError("克隆不支持异常");
        }
    }
}

// 测试类
class Main {
    public static void main(String[] args) {
        Sheep original = new Sheep("多利", 3);
        System.out.println("原对象: " + original);
        System.out.println("原对象Hash: " + original.hashCode());

        // 克隆对象
        Sheep cloned = original.clone();
        
        System.out.println("克隆对象: " + cloned);
        System.out.println("克隆对象Hash: " + cloned.hashCode());

        // 验证：两个对象不是同一个实例，但属性值相同
        System.out.println("original == cloned ? " + (original == cloned)); // false
    }
}

```



### 3. 浅拷贝 vs 深拷贝 (Shallow vs. Deep Copy) —— **重难点**
*   **浅拷贝 (Shallow)**：`super.clone()` 的默认行为。只复制基本数据类型的值和对象的引用地址。如果对象包含引用类型字段（如数组、其他对象），原对象和克隆对象会共享这些引用。
*   **深拷贝 (Deep)**：在 `super.clone()` 之后，手动将引用类型的字段也克隆一份。

**课件中的经典案例 (Course1 类 - 数组的深拷贝)**：
如果不做深拷贝，修改副本的 `students` 数组，原对象的数组也会被修改！

```java
// 假设类中有字段：String[] students = new String[100];

@Override
public Object clone() {
    try {
        // 1. 先进行浅拷贝
        Course1 c = (Course1)super.clone(); 
        
        // 2. 处理引用类型字段 (数组) - 关键步骤！
        if (this.students != null) {
            c.students = new String[this.students.length];
            // 将原数组内容复制到新数组中
            System.arraycopy(this.students, 0, c.students, 0, this.students.length);
        }
        return c;
    } catch (CloneNotSupportedException e) {
        return null;
    }
}
```

```java
class Address implements Cloneable {
    private String city;

    public Address(String city) {
        this.city = city;
    }

    public String getCity() { return city; }
    public void setCity(String city) { this.city = city; }

    // Address 也需要支持克隆
    @Override
    protected Address clone() {
        try {
            return (Address) super.clone();
        } catch (CloneNotSupportedException e) {
            throw new AssertionError();
        }
    }
}

public class Person implements Cloneable {
    private String name;
    private Address address; // 引用类型

    public Person(String name, Address address) {
        this.name = name;
        this.address = address;
    }

    // Getter 和 Setter
    public Address getAddress() { return address; }

    @Override
    protected Person clone() {
        try {
            // 1. 先完成浅拷贝（复制 name 和 address 的引用）
            Person person = (Person) super.clone();
            
            // 2. 【关键步骤】手动克隆引用类型对象，实现深拷贝
            // 这样，新 person 对象的 address 就是一个全新的对象了
            person.address = this.address.clone();
            
            return person;
        } catch (CloneNotSupportedException e) {
            throw new AssertionError();
        }
    }
}

// 测试深拷贝
class DeepCopyTest {
    public static void main(String[] args) {
        Address addr = new Address("北京");
        Person p1 = new Person("张三", addr);

        // 进行深拷贝
        Person p2 = p1.clone();

        System.out.println("克隆前 p1 地址: " + p1.getAddress().getCity());
        System.out.println("克隆前 p2 地址: " + p2.getAddress().getCity());

        // 修改克隆对象 p2 的地址
        p2.getAddress().setCity("上海");

        System.out.println("----------------");
        System.out.println("修改后 p1 地址: " + p1.getAddress().getCity()); // 应该还是 "北京"
        System.out.println("修改后 p2 地址: " + p2.getAddress().getCity()); // 变成了 "上海"
        
        // 如果是浅拷贝，p1 的地址也会变成上海。但在深拷贝中，p1 不受影响。
    }
}

```

## 四、 抽象类 vs 接口 (面试与考试高频)

| 特性         | 抽象类 (Abstract Class)                                 | 接口 (Interface)                                             |
| :----------- | :------------------------------------------------------ | :----------------------------------------------------------- |
| **关系**     | **Is-a** (Strong relationship, e.g., Staff is a Person) | **Is-kind-of** / **Can-do** (Weak relationship, e.g., String is Comparable) |
| **数据成员** | 可以有各种类型的变量                                    | 只能有常量 (`public static final`)                           |
| **构造方法** | 有 (供子类调用)                                         | 无 (不能被实例化)                                            |
| **方法实现** | 可以有具体方法                                          | 只有抽象方法 (Java 8前)                                      |
| **继承限制** | **单继承** (一个类只能 extends 一个父类)                | **多实现** (一个类可以 implements 多个接口)                  |
| **根**       | 所有类最终继承自 `Object`                               | 接口没有单一的根，但接口类型的引用变量可以转为 Object        |

## 五、 Java 与 C++ 的核心区别 (针对软工学生)

在学习 Java 面向对象时，软工学生容易混淆 C++ 的概念，这里是对比：

1.  **接口的概念**：
    *   **C++**：没有 `interface` 关键字。C++ 使用**纯虚类**（只包含纯虚函数的类）来模拟接口。
    *   **Java**：有专门的 `interface` 关键字，语义更清晰。

2.  **多重继承**：
    *   **C++**：允许**多重继承类**（`class A : public B, public C`），这会导致“菱形继承”问题（Diamond Problem），非常复杂。
    *   **Java**：禁止类的多重继承（单根继承），但允许**接口的多重实现**（`class A implements B, C`）。这是 Java 设计上为了避免 C++ 复杂性所做的取舍。

3.  **抽象方法语法**：
    *   **C++**：`virtual void draw() = 0;`
    *   **Java**：`public abstract void draw();`

4.  **指针与引用**：
    *   在讲 `clone` 时要注意，Java 没有指针算术，所有对象变量本质上都是**引用**（类似于 C++ 的指针，但更安全）。这就是为什么默认的浅拷贝只复制了地址。

## 六、 考试易错坑点 (Pitfalls)

1.  **实例化错误**：
    *   ❌ `GeometricObject g = new GeometricObject();` (编译错误，抽象类不可实例化)
    *   ❌ `Comparable c = new Comparable();` (编译错误，接口不可实例化)
    *   ✅ `GeometricObject g = new Circle();` (正确，多态)
    *   ✅ `GeometricObject[] a = new GeometricObject[10];` (正确，这是创建数组对象，数组内存放引用的空位，并没有实例化具体的几何对象)。

2.  **访问修饰符陷阱**：
    *   在接口中定义方法时，可以省略 `public abstract`。
    *   但是在**实现类**中重写该方法时，**必须显式加上 `public`**！
    *   *原因*：子类重写父类方法时，访问权限不能降低。接口默认是 public，如果不写 public，类中默认是 package-private (default)，权限降低了，会导致编译错误。

3.  **Comparable 的泛型**：
    *   如果定义类时写了 `implements Comparable<Circle>`，那么 `compareTo` 的参数必须是 `Circle`。
    *   如果写成 `implements Comparable` (Raw type)，那么参数必须是 `Object`，然后需要在方法内部强转，不仅不安全还容易扣分。

4.  **Clone 的异常**：
    *   调用 `super.clone()` 必须放在 `try-catch` 块中，或者在方法签名上声明 `throws CloneNotSupportedException`，这是编译强制检查的异常（Checked Exception）。
