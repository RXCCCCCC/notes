## Query有什么作用

`Query` 是一个非常核心且强大的工具函数。它的主要作用是**显式地定义、校验和描述 URL 请求中的“查询参数”（Query Parameters）**。

虽然在 FastAPI 中，**就算不写 `Query` 也能接收参数，但使用 `Query` 会赋予你几个关键的“超能力”。**结合你刚才代码中的例子，它的作用主要体现在以下四个方面：

### 1. 设置默认值

当你把一个值作为 `Query` 的**第一个参数传入时，它就成了这个变量的默认值。**

- **代码例子：** `page: int = Query(1, ...)`
- **作用：** **如果前端在请求网址时没有带上 `page` 参数（比如直接访问 `.../list`）**，FastAPI 会**自动将其当作 `page=1` 来处理，而不会报错说缺少参数**。

### 2. 增加严格的数据校验（Validation）

这是 `Query` 最重要的功能之一，它可以**防止不合法的数据进入你的核心代码。**

- **代码例子：** `ge=1` 和 `le=100`
- **作用：** * `ge=1` 代表 **G**reater than or **E**qual，即“大于或等于 1”。它**防止了前端传来 `page=0` 或负数导致数据库查询出错。**
	- `le=100` 代表 **L**ess than or **E**qual，即“小于或等于 100”。它**限制了 `page_size`（每页数量）最大不能超过 100，防止有人恶意请求几万条数据把服务器弄崩。**
- **优势：** 如果前端**传了不符合规定的值（比如 `?page=-5`），FastAPI 会在门口自动拦截**，并直接给前端返回一个**友好的 422 错误提示（告诉他数据校验失败），而完全不需要你手动去写 `if page < 1:` 这样的判断语句。**

### 3. 设置参数别名（Alias）

用于**解决前后端命名规范不一致的问题。**

- **代码例子：** `alias="pageSize"`
- **作用：** Python 后端程序员**习惯用下划线命名法（`page_size`），而前端和 URL 传参习惯用驼峰命名法（`?pageSize=10`）。加上别名后，前端可以理直气壮地传 `pageSize`，FastAPI 会自动把它对应给后端的 `page_size` 变量。**

### 4. 自动生成 API 文档

FastAPI 自带**生成 Swagger UI 可视化接口文档的功能。你用 `Query` 写的这些规则（默认值、大于等于几、小于等于几等），都会被框架自动提取**，并显示在 API 文档上，**方便前端同学查阅和调试。**

------

**💡 一句话总结：** `Query` 就像是一个**智能的门卫兼翻译官**。它负责**把前端 URL 问号后面带的参数（如 `?page=2&pageSize=20`）接过来**，检查一下是否合法，**遇到别名顺便翻译一下，如果有人乱传数据就直接挡在门外，极大地简化了后端的开发工作。**

**带有缓存机制的数据查询（Cache-Aside Pattern）**。

它的核心思想是：**优先去速度极快的“缓存”（比如 Redis）里找数据，找不到的话再去相对较慢的“数据库”（比如 MySQL）里找，找到之后把它存到缓存里，方便下次直接读取。**

我们依然按照逻辑步骤，把代码分为四个部分为你详细拆解：

### 1. 函数定义与参数接收

- **`async def get_categories(db: AsyncSession, skip: int=0, limit: int=100):`**
	- 这是一个名为 `get_categories`**（获取分类）的异步函数。**
	- `db: AsyncSession`：**接收一个数据库会话对象**，用于**后续的数据库操作。**
	- `skip: int=0`：**跳过的记录数（偏移量）**，默认是 0。常用于分页，比如**想看第 2 页（每页10条），这里就会传入 10。**
	- `limit: int=100`：**限制返回的最大记录数**，默认**最多返回 100 条**。这也是为了分页和保护数据库。

------

### 2. 第一步：尝试读取缓存 (Cache Hit)

- **`cached_categories = await get_cached_categories()`**
	- 程序首先调用一个专门读缓存的函数，尝试从内存/缓存服务器中获取“新闻分类”的数据。
- **`if cached_categories:`**
	- 判断缓存里有没有数据。
- **`return cached_categories`**
	- **“缓存命中”**：如果缓存里有数据，直接返回给前端！**程序到此结束，根本不需要去查询数据库。** 这是提升接口响应速度和减轻数据库压力的关键。

------

### 3. 第二步：查询数据库 (Cache Miss / Fallback)

如果代码运行到了这里，说明缓存里没有数据（也就是所谓的“缓存未命中”），必须去数据库里老老实实地查了。

- **`stmt = select(Category).offset(skip).limit(limit)`**
	- 使用 **SQLAlchemy 构建查询语句**：**查询 `Category`（分类表），跳过前 `skip` 条，最多取 `limit` 条。**
- **`result = awaitdb.execute(stmt)`**
	- *(注：这里截图中的代码有一个小拼写错误，应该是 `await db.execute(stmt)`，中间少了个空格)*。这行代码的意思是**让数据库真正去执行上面构建的查询语句**。
- **`categories = result.scalars().all()`**
	- 将数据库返回的原始结果，提取**转换成 Python 的对象列表（也就是包含多个分类对象的 List）。**

------

### 4. 第三步：更新缓存并返回结果

既然辛辛苦苦从数据库查到了数据，就要把**它存进缓存里**，这样下一次有人再请求同样的接口时，就可以直接走“第一步”的捷径了。

- **`if categories:`**
	- 如果数据库里**确实查到了数据（不是空列表）**。
- **`categories = jsonable_encoder(categories)`**
	- 这是 FastAPI 提供的一个实用工具。因为数据库查询出来的 `Category` 模型**对象可能包含一些无法直接存入缓存（通常缓存只认字符串或 JSON）**的特殊格式，这个函数负责**把复杂的对象转换成标准的、可被 JSON 序列化的字典（Dict）格式**。
- **`await cache_categories(categories)`**
	- 调用写入缓存的函数，把刚刚转换好的数据存进缓存中。
- **`return categories`**
	- 最后，将查询到的数据返回给调用方（前端）。

## 前缀 "Bearer "是干嘛的

`Bearer ` 是放在 HTTP 请求头 `Authorization` 里的**认证前缀**，意思是：

> “后面跟的是一个可直接使用的访问令牌（token）”。

常见格式是：

```
Authorization: Bearer xxx.yyy.zzz
```

### 它的作用

- 告诉后端：**这是一个 Bearer Token**
- 后端据此去解析、校验这个 token
- 如果 token 有效，就允许访问受保护接口

### 为什么要加这个前缀

- 这是**业界标准写法**
- 便于**区分不同认证方式，**比如：
	- `Bearer`：令牌认证
	- `Basic`：用户名密码编码认证

### 结合你这个项目

你项目文档里写的是：

```
Authorization: token值
```

但如果**后端代码按标准 `Bearer` 方式解析，那请求头就应该写成：**

```
Authorization: Bearer token值
```
