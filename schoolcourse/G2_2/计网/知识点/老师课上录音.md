# 1. 第一章：计算机网络概述

## 1.1 什么是互联网 Internet

需要掌握两个角度：

1. **从组成部件看**
	- 主机 host / 端系统 end system
	- 路由器 router
	- 链路 link
	- 接入网 access network
	- 局域网 LAN
	- 广域网 WAN
2. **从服务角度看**
	- 互联网为应用程序提供通信服务
	- 应用层程序通过下层协议栈完成端到端通信

老师强调：那张“整个互联网结构大图”要能在脑子里串起来，包括广域网、局域网、接入网、主机、路由器等。

## 1.2 网络边缘 Network Edge

考点：

1. 网络边缘由各种接入网组成。
2. 接入网中包含主机，也叫端系统 end system。
3. 主机角色：
	- client 客户端
	- server 服务器
4. 三类接入网：
	- residential access 居民接入网
	- institutional access 机构接入网
	- mobile access 移动接入网
5. 要能分辨不同接入网中主要设备和连接方式。

## 1.3 网络核心 Network Core

核心考点：

1. 网络核心主要由 router 路由器组成。
2. 路由器通过链路连接形成网状转发网络。
3. 两种交换方式：
	- packet switching 分组交换
	- circuit switching 电路交换

### 分组交换 Packet Switching

必会：

1. 核心机制：**store-and-forward 存储转发**
2. 路由器必须完整接收一个分组后，才能转发到输出端口。
3. 不能“一边收一边发”。

### 分组交换 vs 电路交换

重点比较：

| 对比点           | 分组交换 Packet Switching | 电路交换 Circuit Switching |
| ---------------- | ------------------------- | -------------------------- |
| 是否建连接       | 通常不预先建专用连接      | 先建立连接                 |
| 是否预留资源     | 不预留资源                | 预留带宽/缓存等资源        |
| 是否适合突发数据 | 适合 bursty data          | 不太适合                   |
| 支持用户数       | 可支持更多用户统计复用    | 受预留资源限制             |
| 典型代表         | Internet                  | 电话网思想                 |

老师特别强调：分组交换适合 bursty data，因为用户不是一直发送数据，可以支持更多用户共享网络资源。

## 1.4 分组交换网性能

必会四类 delay：

1. **processing delay 处理时延**
	- 节点检查分组头、差错检测、决定转发端口等。
2. **queueing delay 排队时延**
	- 分组在路由器队列中等待。
	- 和网络拥塞程度有关。
3. **transmission delay 传输时延**
	- 把所有比特推到链路上的时间。
	- 公式：$d_{trans}=\frac{L}{R}$
	- $L$ 是分组长度，$R$ 是链路速率。
4. **propagation delay 传播时延**
	- 比特在物理链路上传播的时间。
	- 公式：$d_{prop}=\frac{d}{s}$
	- $d$ 是距离，$s$ 是传播速度。

还要掌握：

1. total nodal delay 总结点时延
2. end-to-end delay 端到端时延
3. throughput 吞吐量
4. bottleneck link 瓶颈链路：端到端路径中吞吐量最小的链路。

## 1.5 协议分层与参考模型

必会：

1. **OSI 七层模型**
	- Physical
	- Data Link
	- Network
	- Transport
	- Session
	- Presentation
	- Application
2. **TCP/IP 五层模型**
	- Application 应用层
	- Transport 传输层
	- Network 网络层
	- Data Link 数据链路层
	- Physical 物理层
3. 每层 PDU 名称：
	- Application：message 报文
	- Transport：segment 报文段
	- Network：datagram 数据报
	- Data Link：frame 帧
	- Physical：bit 比特
4. 封装 encapsulation：
	- 发送方：应用层数据逐层向下，每层加 header，数据链路层还可能加 trailer。
	- 接收方：逐层向上，逐层去掉 header/trailer。
5. 每层典型协议：
	- Application：HTTP、SMTP、DNS、FTP 等
	- Transport：TCP、UDP
	- Network：IP、ICMP
	- Data Link：Ethernet、ARP 相关链路层封装

# 2. 第二章：应用层 Application Layer

## 2.1 应用程序对传输层的需求

要掌握不同应用对 transport service 的需求：

1. reliable data transfer 可靠传输需求
2. timing 实时性需求
3. throughput 吞吐量需求
4. security 安全性需求
5. 是否能容忍 packet loss

典型判断：

- 文件传输、邮件、网页：不能丢，通常用 TCP。
- 实时音视频：可容忍少量丢失，但重视实时性，可能用 UDP。
- DNS：通常用 UDP。
- HTTP：通常用 TCP。

## 2.2 C/S 与 P2P 架构

### Client-Server 架构

掌握：

1. 有固定服务器。
2. 服务器长期在线。
3. 服务器有固定 IP 或域名。
4. 客户端主动请求服务。
5. 可扩展性受服务器能力限制。

### P2P 架构

掌握：

1. peer 对等体既是客户端又是服务器。
2. 节点可以随时加入或离开。
3. 自扩展 self-scalability。
4. 每个节点既请求资源，也提供资源。
5. 典型应用：BitTorrent 类 P2P 文件共享。

老师要求能比较 C/S 和 P2P 的架构特点。

## 2.3 HTTP

必会：

### HTTP 请求报文 Request Message

掌握：

1. request line 请求行
2. method 方法：
	- GET
	- POST
	- HEAD
	- PUT
	- DELETE
3. header lines 头部行
4. 常见字段含义：
	- Host
	- User-Agent
	- Connection
	- If-Modified-Since

### HTTP 响应报文 Response Message

掌握：

1. status line 状态行
2. status code 状态码：
	- 200 OK
	- 301 Moved Permanently
	- 304 Not Modified
	- 400 Bad Request
	- 404 Not Found
	- 505 HTTP Version Not Supported

### Persistent vs Non-persistent HTTP

1. **Non-persistent connection 非持久连接**
	- 每传一个对象建立一次 TCP 连接。
	- 传完关闭。
2. **Persistent connection 持久连接**
	- 一个 TCP 连接上传多个对象。
	- 性能更好。

### HTTP 无状态 Stateless

必会：

1. HTTP 本身不维护客户端状态。
2. 服务器不会天然记住“哪个用户之前访问过什么”。

### Cookie

掌握 Cookie 作用和组成：

1. 作用：在 HTTP 无状态基础上维护用户状态。
2. 四个组成部分：
	- HTTP response 中的 cookie header line
	- HTTP request 中的 cookie header line
	- 用户浏览器端 cookie file
	- 服务器端数据库

### Web Cache / Proxy Server

掌握：

1. Web cache 代理服务器可以缓存访问过的网页对象。
2. 作用：
	- 加快本地用户访问
	- 降低接入链路 access link 流量
	- 减少远程服务器压力

### Conditional GET

必会：

1. 用于代理缓存与原服务器之间确认缓存是否过期。
2. 关键头部：If-Modified-Since。
3. 如果资源未修改，服务器返回 304 Not Modified，不必传输对象主体。
4. 作用：节省网络流量。

## 2.4 Email 电子邮件

考点：

1. 邮件系统组成：
	- user agent 用户代理
	- mail server 邮件服务器
	- SMTP
	- POP3 / IMAP
2. SMTP 用于发送邮件：
	- 发件人用户代理到发件人邮件服务器
	- 发件人邮件服务器到收件人邮件服务器
3. SMTP 基于 TCP，因为邮件要求完整可靠。
4. POP3 / IMAP 用于收邮件：
	- 收件人从自己的邮件服务器取邮件。

## 2.5 DNS

必会：

1. DNS 作用：domain name $\rightarrow$ IP address。
2. 层次结构：
	- root DNS server 根域名服务器
	- TLD server 顶级域名服务器
	- authoritative DNS server 权威域名服务器
	- local DNS server 本地域名服务器
3. 每类 DNS 服务器保存什么信息、负责什么查询。
4. 查询方式：
	- recursive query 递归查询
	- iterative query 迭代查询
5. 要能根据一个查询过程判断是递归还是迭代。
6. 也要能描述从 local DNS server 开始的查询流程。

# 3. 第三章：传输层 Transport Layer

## 3.1 传输层服务

重点：

1. 网络层提供 host-to-host 主机到主机通信。
2. 传输层提供 process-to-process 进程到进程通信。
3. TCP 提供较完整服务：
	- reliable data transfer
	- flow control
	- congestion control
	- connection management
4. UDP 基本只提供进程到进程交付和校验。

## 3.2 Multiplexing / Demultiplexing

### Multiplexing 复用

发送方传输层把多个应用进程的数据封装成 TCP segment 或 UDP segment。

### Demultiplexing 分用

接收方传输层根据头部信息把 segment 交给正确 socket / process。

### UDP 分用

UDP 根据：

1. destination IP
2. destination port

即二元组。

### TCP 分用

TCP 根据四元组：

1. source IP
2. source port
3. destination IP
4. destination port

### 常见端口号

要记：

1. HTTP：80 / 8080
2. **DNS：53**
3. SMTP：25
4. POP3：110
5. FTP：20 / 21
6. **Telnet：23**
7. 1024 以下是 well-known ports 著名端口。

## 3.3 UDP

考点：

1. UDP header 结构：
	- source port
	- destination port
	- length
	- checksum
2. UDP 特点：
	- connectionless 无连接
	- unreliable 不可靠
	- no flow control
	- no congestion control
	- header 简单
3. UDP checksum 的作用：
	- 检测端到端传输中的错误或篡改。
	- 不是只为了端口分用，校验字段也要关注。

## 3.4 Reliable Data Transfer

必会：

### rdt 版本演进

1. rdt1.0：信道完全可靠。
2. rdt2.0：处理 bit error，引入 checksum、ACK、NAK。
3. rdt2.1 / rdt2.2：处理 ACK/NAK 出错，引入 sequence number。
4. rdt3.0：处理 packet loss，引入 timeout 和 retransmission。

要会回答：

- 每个版本解决什么问题？
- 引入了什么机制？

### GBN vs SR

重点比较：

| 项目         | GBN                         | SR                                                        |
| ------------ | --------------------------- | --------------------------------------------------------- |
| 确认机制     | **cumulative ACK 累计确认** | **individual ACK 单独确认**                               |
| 定时器       | **通常一个定时器**          | **每个未确认分组一个定时器**                              |
| 接收方缓存   | 只按序接收，乱序丢弃        | 可缓存乱序分组                                            |
| 重传方式     | 从丢失分组开始回退重传      | 只重传丢失分组                                            |
| 接收窗口     | 通常为 1                    | 大于 1                                                    |
| 序号空间要求 | 注意窗口与序号空间关系      | $N_s+N_r \leq$ 序号空间，常见要求**窗口小于序号空间一半** |

老师特别强调 GBN 和 SR 要比较确认机制、计时器机制、接收方缓存。

## 3.5 TCP

这是第三章最重要部分。

### TCP Segment 结构

掌握主要字段：

1. source port
2. destination port
3. sequence number
4. acknowledgment number
5. receive window
6. checksum
7. flags：SYN、FIN、RST、ACK 等

### TCP 序号与确认号

必会计算：

1. TCP 按字节编号 byte-oriented。
2. segment 的 sequence number 是该 segment 中第一个字节的编号。
3. ACK number 是“下一个期望收到的字节编号”。
4. 如果 seq = 60，携带 20 bytes，则字节范围是 60–79，ACK = 80。

这是很可能考计算/过程分析的点。

### TCP 可靠传输机制

掌握：

1. checksum
2. sequence number
3. ACK
4. timeout retransmission
5. duplicate ACK
6. cumulative ACK

### TCP 连接管理

掌握：

1. three-way handshake 三次握手。
2. SYN 用于建立连接。
3. FIN 用于关闭连接。
4. RST 用于重置连接。
5. 要能判断每个包的控制位含义。

### Flow Control 流量控制

核心：

1. receiver window 接收窗口由接收方通告。
2. 发送方不能超过接收方缓存能力。
3. 防止把接收方“撑爆”。

### Congestion Control 拥塞控制

必会：

1. TCP 实际发送窗口由两个窗口共同决定：

$SendWindow = min(cwnd, rwnd)$

其中：

- $cwnd$：congestion window 拥塞窗口
- $rwnd$：receive window 接收窗口

1. 如果题目只讨论拥塞控制，通常默认发送窗口由 $cwnd$ 决定。

### TCP 感知拥塞的两个事件

1. timeout 计时器超时
2. triple duplicate ACK 三次重复确认

### 慢启动 Slow Start

1. 初始 $cwnd = 1 MSS$。
2. 阈值 ssthresh 以下指数增长。
3. 大致变化：1，2，4，8……
4. 如果即将超过 ssthresh，要先停在 ssthresh。

### 拥塞避免 Congestion Avoidance

1. 超过阈值后线性增长。
2. 每个 RTT 约增加 1 MSS。

### Tahoe / Reno 差异

老师口头提到旧版本和新版本：

1. **TCP Tahoe**
	- 不管 timeout 还是 triple duplicate ACK：
		- $ssthresh = \frac{cwnd}{2}$
		- $cwnd = 1 MSS$
		- **重新慢启动**
2. **TCP Reno**
	- timeout：
		- $ssthresh = \frac{cwnd}{2}$
		- $cwnd = 1 MSS$
		- 重新慢启动
	- triple duplicate ACK：
		- $ssthresh = \frac{cwnd}{2}$
		- $cwnd = ssthresh + 3 MSS$
		- 进入 fast recovery 快速恢复

### 必会图像题

要能根据曲线判断：

1. 哪几轮是 slow start。
2. 哪几轮是 congestion avoidance。
3. 哪里发生 timeout。
4. 哪里发生 triple duplicate ACK。
5. ssthresh 如何变化。
6. cwnd 如何变化。

老师明确强调教材图 3.51、3.52 的 FSM 和曲线图要理解，会根据传输轮次写出阶段。

# 4. 第四章：网络层 Network Layer

## 4.1 网络层两个核心功能

必会：

1. forwarding 转发
	- 路由器把到达输入端口的分组转到合适输出端口。
2. routing 路由
	- 计算从源到目的的路径。

## 4.2 虚电路网络 vs 数据报网络

| 项目         | Virtual Circuit Network | Datagram Network     |
| ------------ | ----------------------- | -------------------- |
| 对应交换思想 | **电路交换思想**        | **分组交换思想**     |
| 是否建连接   | **先建连接**            | **不预先建连接**     |
| 是否预留资源 | **通常预留**            | **不预留**           |
| 分组携带信息 | 虚电路号 VC number      | 完整目的地址         |
| 路由方式     | 同一连接**路径固定**    | 每个分组**独立转发** |
| 典型代表     | 虚电路子网              | Internet 数据报网络  |

老师强调要搞清楚：电路交换/分组交换与虚电路网络/数据报网络之间的对应关系。

## 4.3 路由器结构

必会：

1. **router input port 输入端口**
2. **router output port 输出端口**
3. **switching fabric 交换结构**
4. 每个端口有**完整的三层协议栈：**
	- **physical**
	- **data link**
	- **network**

### Longest Prefix Matching 最长前缀匹配

重点：

1. 路由表中不是写每一台主机的完整 IP，而**是写 network prefix 网络前缀。**
2. **一个前缀代表一个网段中的许多主机。**
3. 好处：
	- **缩短路由表**
	- **节省路由器存储**
	- **提高查找效率**

老师明确要求理解“为什么路由表用前缀而不是完整 IP 地址”。

### Head-of-Line Blocking 头部阻塞

掌握：

1. 发生位置：input port 输入端口。
2. 原因：队首分组因目标输出端口忙而阻塞，后面的分组即使可走其他端口也被挡住。
3. 本质：**到达输入端口的速率超过交换结构/输出端口处理能力**。
4. 解决思路：提高**交换结构转发速率，使其大于输入到达速率**。

## 4.4 IPv4

这是第四章重头戏。

### IPv4 Header

掌握头部字段含义，尤其：

1. version
2. header length
3. type of service
4. total length
5. identification
6. flags
7. fragment offset
8. TTL
9. protocol
10. header checksum
11. source IP
12. destination IP

### IPv4 Fragmentation 分片

必会计算：

1. 分片原因：不同链路 MTU 不同。录音里老师口头说 MSS，但网络层分片应按教材理解为 MTU。
2. **IPv4 支持路由器分片。**
3. **IPv6 路由器不再做分片。**
4. 分片相关字段：
	- identification：标识属于同一个原始 datagram
	- flags：是否允许分片、是否最后一片等
	- fragment offset：片偏移，以 8 bytes 为单位

可能考法：

- 给一个大 IP datagram。
- 给每条链路 MTU。
- 要求算每片数据大小、offset、MF 标志、总长度等。
- 如果 DF = 1 且需要分片，则路由器丢弃并返回 ICMP error。

老师强调 IPv4 分片字段和例题要掌握。

## 4.5 IP 地址与子网划分

高频计算：

1. IP 地址由 network part 和 host part 构成。
2. 会根据 IP/prefix 求：
	- network address 网络地址
	- broadcast address 广播地址
	- usable host range 可用主机范围
	- usable host number 可用主机数
3. subnetting 子网划分：
	- 给一个大网段，划分成若干子网。
	- 例如划分成 8 个子网，需要借 3 位。
4. route aggregation 路由聚集：
	- 给多个连续小网段，聚合成一个大前缀。
	- 目的：减少路由表项。

老师说 IP 地址计算“可以五花八门”，书上和课件讲过的都可能涉及。

## 4.6 DHCP

掌握：

1. DHCP 用于动态分配 IP 地址。
2. DHCP 是应用层协议，但服务于网络层地址配置。
3. 传输层通常使用 UDP。
4. 有 client 和 server。
5. 基本交互过程：
	- DHCP Discover
	- DHCP Offer
	- DHCP Request
	- DHCP ACK

老师说不会让大家很复杂地写全过程，但相关概念要懂。

## 4.7 ICMP 与 Traceroute

必会：

1. ICMP 是网络层协议。
2. 作用：
	- error reporting 错误报告
	- network diagnostics 网络诊断

### Traceroute / Tracert

重点过程：

1. 发送探测包，TTL 从 1 开始。
2. 第一次通常发 3 个 TTL = 1 的探测包。
3. 路由器收到后 TTL 减 1。
4. TTL 变为 0 时丢弃包，返回 ICMP TTL exceeded。
5. 发送方据此知道该跳路由器的 IP/名称。
6. TTL 逐步增加，直到到达目标主机。
7. 最后目标主机返回 ICMP port unreachable，探测结束。

老师强调 traceroute 如何基于 ICMP 实现，前面靠 TTL exceeded，最后靠 port unreachable 结束。

## 4.8 NAT

必会：

1. NAT 用于内网地址和公网地址转换。
2. NAT 表不仅映射 IP，还映射端口号。
3. 映射形式类似：

$(private\ IP, private\ port) \leftrightarrow (public\ IP, public\ port)$

1. 必须先由内网主机向外发起通信，NAT 建立映射。
2. 外部主机不能无映射地直接访问内网主机。
3. 返回包根据 NAT 表转换回内网地址和端口。

## 4.9 IPv6

掌握：

1. IPv6 地址长度：128 bits。
2. IPv4 地址长度：32 bits。
3. IPv6 与 IPv4 报文头差异。
4. IPv6 不在路由器中进行分片。
5. 哪些字段被取消、简化或改名，要对照课件掌握。

## 4.10 Routing Algorithms 路由算法

### Link State 链路状态算法

必会：

1. 每个节点构造 link-state packet。
2. 通过 flooding 洪泛让所有节点获得完整网络拓扑。
3. 每个节点根据完整拓扑运行 Dijkstra 算法。
4. 算出从自己到其他所有节点的 shortest path。
5. 重点是会算 Dijkstra 表。

### Distance Vector 距离矢量算法

必会：

1. 每个节点维护距离矢量表。
2. 节点只和邻居交换距离矢量。
3. 收到邻居表后用 Bellman-Ford 更新。
4. 要会手算表格更新。

### 好消息传得快，坏消息传得慢

必须会解释原因：

1. 好消息**每经过一跳就能快速传播。**
2. **坏消息慢，是因为节点只交换“可达距离”，不交换完整路径。**
3. 节点**不知道邻居到某目的节点是否其实经过自己。**
4. 因此**会出现 count-to-infinity 现象。**

老师特别强调“坏消息传得慢”的原因要讲清楚。

## 4.11 Internet 路由协议

掌握两级路由：

### AS 内部路由 Intra-AS Routing

1. 关注性能、路径长短、速度。
2. 典型协议：
	- RIP
	- OSPF
3. RIP 基于 distance vector。
4. OSPF 基于 link state。

### AS 之间路由 Inter-AS Routing

1. 典型协议：BGP。
2. 更关注策略 policy 和可达性 reachability。
3. 不只是最短路径问题。

# 5. 第五章：数据链路层 Data Link Layer

## 5.1 差错检测 Error Detection

了解：

1. 数据链路层需要发现传输错误。
2. CRC 是重点。

## 5.2 CRC 循环冗余检测

必会计算：

1. 发送方：
	- 给定 data bits 和 generator polynomial。
	- 在数据后补 0。
	- 做模 2 除法。
	- 得到 remainder。
	- 把 remainder 作为 EDC/FCS 加到数据尾部。
2. 接收方：
	- 用相同 generator 对收到的比特串做模 2 除法。
	- 余数为 0，认为无错。
	- 余数非 0，检测到错误。

老师强调 CRC 的计算方法、发送方怎么做、接收方怎么检查都要清楚。

## 5.3 Multiple Access Protocols 多路访问协议

三类：

1. channel partitioning protocols 信道划分协议
	- TDMA
	- FDMA
	- CDMA
2. random access protocols 随机访问协议
	- ALOHA
	- CSMA
	- CSMA/CD
3. taking-turns protocols 轮流协议
	- polling
	- token passing

### CSMA/CD

重点掌握过程：

1. 发送前**先监听信道。**
2. **信道空闲才发送。**
3. **边发送边监听。**
4. **如果检测到冲突：**
	- **立即停止发送**
	- **发送 jam signal 阻塞信号**
	- **执行 binary exponential backoff 二进制指数退避**
5. 退避**结束后重新监听信道。**

老师明确说 CSMA/CD 的算法过程和二进制退避要了解。

## 5.4 MAC 地址与 IP 地址

必会比较：

| 项目                 | IP Address                | MAC Address          |
| -------------------- | ------------------------- | -------------------- |
| 层次                 | 网络层                    | 数据链路层           |
| 类型                 | **分层地址 hierarchical** | **平面地址 flat**    |
| 作用范围             | 跨网络寻址                | 局域网内交付         |
| **是否体现网络结构** | **是**                    | **否**               |
| 是否通常随网络变化   | 会变                      | 网卡物理地址相对固定 |

核心理解：

1. IP 负责把数据送到目标网络。
2. MAC 负责在当前局域网内把帧送到下一跳或目标主机。

## 5.5 ARP

这是数据链路层综合题核心。

### ARP 作用

1. ARP 完成 IP address $\rightarrow$ MAC address 的映射。
2. 每台主机维护 ARP table。
3. 构造 Ethernet frame 时必须**填写 destination MAC。**
4. 只知道目标 IP 不够，必须通过 ARP 得到 MAC。

### 同一局域网 ARP 查询过程

1. A 要给 B 发数据。
2. A 查 ARP 表，没有 B 的 MAC。
3. A 广播 ARP request。
4. ARP request 封装在以太网帧中：
	- source MAC = A 的 MAC
	- destination MAC = FF:FF:FF:FF:FF:FF
5. 局域网所有主机收到。
6. 只有 IP 等于目标 IP 的 B 响应。
7. B 单播 ARP reply 给 A：
	- source MAC = B 的 MAC
	- destination MAC = A 的 MAC
8. A 更新 ARP 表，之后可正常封装帧。

老师强调为什么需要 ARP，以及 ARP 请求广播、响应单播的过程。

### 跨局域网通信

必会综合分析：

1. IP 源地址和目的地址端到端不变。
2. MAC 地址每一跳都会变化。
3. 如果目标不在同一局域网，源主机先把帧发给默认网关 router。
4. 源主机 ARP 查询的是默认网关接口的 MAC，不是远端主机 MAC。
5. 每经过一个路由器，重新封装新的链路层帧。
6. 要能根据拓扑填写每一段链路的：
	- source IP
	- destination IP
	- source MAC
	- destination MAC

老师明确说综合题可能给一个网络拓扑，让你根据已知信息推 IP/MAC 地址、网段信息和封装过程。

## 5.6 Ethernet Switch 交换机

必会：

1. 交换机工作在数据链路层。
2. 维护 switch table / forwarding table。
3. 表项主要是：
	- MAC address
	- interface / port

### 自学习 Self-learning

重点过程：

1. 交换机收到帧。
2. 根据帧的 source MAC 学习：
	- 这个 **MAC 位于哪个输入端口。**
3. 如果 destination MAC 不在表中：
	- flood **泛洪到其他端口。**
4. 如果 destination MAC 在表中：
	- **转发到对应**端口。
5. 如果目标端口就是输入端口：
	- 过滤，不转发。

老师特别提醒：交换机**学习时看的是源 MAC，不是目标 MAC。**

## 5.7 交换机 vs 路由器

必会比较：

| 项目       | Switch 交换机          | Router 路由器                                     |
| ---------- | ---------------------- | ------------------------------------------------- |
| 层次       | Data Link Layer        | Network Layer                                     |
| 地址       | MAC address            | IP prefix / IP address                            |
| 表         | switch table           | routing table                                     |
| 表项       | MAC $\rightarrow$ port | network prefix $\rightarrow$ interface / next hop |
| 表生成方式 | self-learning          | routing algorithm / routing protocol              |
| 转发单位   | frame                  | datagram                                          |

## 5.8 VLAN 虚拟局域网

掌握：

1. VLAN 可以在一个物理局域网中划分多个逻辑局域网。
2. 作用：隔离广播域。
3. 不同 VLAN 之间通信需要 router 或三层交换。
4. 跨 VLAN 不能只靠普通二层交换直接完成。

老师强调：跨虚拟局域网交换要通过路由器。

## 5.9 5.7 综合例子：一次网页访问调用哪些协议

这是最后老师强烈建议复习的例子。

要能串起来：

1. 应用层：
	- HTTP 请求网页
	- DNS 解析域名
2. 传输层：
	- HTTP 使用 TCP
	- DNS 通常使用 UDP
	- TCP 三次握手
	- TCP segment 封装
3. 网络层：
	- IP datagram
	- 路由选择
	- 可能涉及 NAT
	- ICMP 可能用于差错报告
4. 数据链路层：
	- ARP 获取下一跳 MAC
	- Ethernet frame 封装
	- 交换机转发
5. 物理层：
	- 比特流在链路上传输

老师说这个例子“非常非常好”，建议复习时重新串起来，因为它能检验你是否知道每个协议在什么阶段运行。
